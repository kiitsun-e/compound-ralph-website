The `design` command runs an autonomous design improvement loop. It takes screenshots of your running application, analyzes the current design, and makes bold styling changes to create distinctive, polished UIs.

## Usage

```bash
cr design [url] [--n iterations]
```

## Arguments

| Argument | Description | Default |
|----------|-------------|---------|
| `url` | URL of running dev server | Auto-detected |
| `--n` | Force exact number of iterations (disables early exit) | 5 |

## What It Does

The design command applies the `/frontend-design` skill philosophy in an iterative loop:

1. **Screenshot** - Captures current state of the target URL
2. **Analyze** - Identifies bland, generic, or "AI-looking" elements
3. **Improve** - Makes bold CSS/styling changes (not subtle tweaks)
4. **Verify** - Takes an after screenshot to confirm improvement
5. **Repeat** - Continues until design is polished or iterations complete

<Aside type="tip">
Each iteration focuses on one section or component. The goal is *distinctive, memorable* design—not safe defaults.
</Aside>

## The `--n` Flag

By default, the design loop may exit early if it determines the design is polished. Use `--n` to force an exact number of iterations:

```bash
# Force exactly 10 iterations, no early exit
cr design http://localhost:3000 --n 10
```

This is useful when:
- You want thorough refinement regardless of the agent's assessment
- Working on complex UIs that need many passes
- Testing the loop's cumulative improvements

Without `--n`, the loop stops when it outputs the completion signal:
```
<design-complete>Design polished.</design-complete>
```

## Auto-Detection

If no URL is provided, `cr design` checks common dev server ports:

| Port | Typical Use |
|------|-------------|
| 3000 | Next.js, Rails, Express |
| 4321 | Astro |
| 5173 | Vite |
| 5174 | Vite (alternate) |
| 8080 | Generic dev servers |

## Design Philosophy

The design loop actively avoids:
- Gray backgrounds
- Generic shadows
- Safe, muted color choices
- Template-looking layouts

It embraces:
- Bold typography
- Intentional whitespace
- Strong visual rhythm
- Personality and craft

## Output Structure

Design sessions are saved to `design-iterations/`:

```
design-iterations/
└── 20260121-143000/
    ├── 01-design.md
    ├── 02-design.md
    └── 03-design.md
```

Each iteration log includes timestamps, the target URL, and the full output.

## Examples

### Auto-detect dev server

```bash
# Start your dev server first
bun run dev &

# Run design loop (auto-detects URL)
cr design
```

### Specify URL and force iterations

```bash
# Force exactly 10 iterations on a specific URL
cr design http://localhost:3000 --n 10
```

### Design after implementation

```bash
# Complete workflow
cr implement specs/feat-landing-page
cr design                           # Polish the UI
cr review --design                  # Get design feedback
```

### Quick polish pass

```bash
# Just a few iterations for touch-ups
cr design --n 3
```

## What Happens Next

After the design loop:

1. **Review changes** - `git diff` to see styling modifications
2. **Run design review** - `cr review --design` for feedback
3. **Commit if satisfied** - Standard git workflow
