Start the autonomous implementation loop. This command reads your SPEC.md and executes tasks one at a time, running quality gates after each iteration.

## Usage

```bash
borg implement [spec-dir]
```

## Arguments

| Argument | Description | Required |
|----------|-------------|----------|
| `spec-dir` | Path to spec directory containing SPEC.md | No (auto-detects) |

## What It Does

The `implement` command runs the Ralph Loop—an autonomous, iterative implementation process:

1. **Reads SPEC.md** to find the next pending task
2. **Executes one task** in a fresh Claude session
3. **Runs quality gates** (tests, lint, build) after each task
4. **Commits changes** with meaningful messages
5. **Repeats** until all tasks are complete

### Key Features

- **Fresh context each iteration** - No degradation over long features
- **File-based state** - Progress survives interrupts; resume anytime
- **Backpressure** - Tests catch errors before they compound
- **Auto-detection** - Finds spec with `status: building` if no path given

## Auto-Detection

When run without arguments, `borg implement` looks for:

1. Fix specs first: `fixes/code/`, `fixes/design/`
2. Then feature specs with `status: building` or `status: pending`

```bash
# These are equivalent if only one spec is active:
borg implement
borg implement specs/my-feature/
```

## Examples

### Start implementing a feature

```bash
borg implement specs/add-user-auth/
```

This starts the loop. You'll see output like:

```
═══════════════════════════════════════════════════════════════
  RALPH BORG - Iteration 1
  Spec: specs/add-user-auth/
═══════════════════════════════════════════════════════════════
Starting task: Install dependencies...
```

### Resume after interruption

```bash
# Ctrl+C to stop, then later:
borg implement
```

The loop picks up where it left off because state lives in SPEC.md.

### Increase iteration limit

By default, the loop runs up to 50 iterations. For larger features:

```bash
MAX_ITERATIONS=100 borg implement specs/large-feature/
```

## The Ralph Loop

Each iteration follows this sequence:

1. **Orient** - Read SPEC.md, find current task
2. **Investigate** - Search for existing code before writing new code
3. **Implement** - Write code and tests together
4. **Validate** - Run quality gates (tests, lint, build)
5. **Update** - Mark task complete, add to iteration log
6. **Commit** - Save progress with descriptive message

### Exit Conditions

The loop stops when:

- All tasks are marked complete
- All exit criteria in SPEC.md are satisfied
- `MAX_ITERATIONS` is reached
- Consecutive failures exceed the threshold

## Failure Handling

When errors occur:

| Scenario | Behavior |
|----------|----------|
| Test failure | Agent attempts to fix in same iteration |
| Consecutive failures | Stops after 5 failures, preserves progress |
| Ctrl+C interrupt | Clean exit, resume with `borg implement` |
| Claude API error | Automatic retry with exponential backoff |

## Output Files

The implement command updates:

| File | Purpose |
|------|---------|
| `SPEC.md` | Task status, iteration log, notes |
| `.borg/learnings.json` | Discovered patterns for future iterations |
| Git commits | One per completed task |

## Tips

- **Start small** - Break tasks into atomic units in your spec
- **Trust backpressure** - Tests catch most issues automatically
- **Check iteration log** - SPEC.md shows what happened each iteration
- **Use fix specs** - Run `borg review` then `borg fix` for cleanup
